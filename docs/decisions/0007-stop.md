# 0007: Stop. SessionScope does not stand as a product

- Date: 2026-11-12
- Author: the person (decided at the end of the day's session), written down by the agent
- Status: accepted. Supersedes 0006 (the offline session analyzer) and, with it, the product
  direction of 0005. The project is paused; nothing is deleted.

## Problem

SessionScope set out to answer a musician's question: *what is eating my DAW's CPU, and where?*
After three weeks, every way of answering it has been built or tested far enough to judge, and
each one fails on at least one requirement the person considers essential.

## The requirements (the person's, stated over 11–12 Nov 2026)

1. **No DAW dependence.** No "supported DAWs" list: every DAW behaves differently and the list
   never ends (`docs/what-failed.md`, the in-session Probe).
2. **No carrying settings over.** "If I have to migrate presets, then no." The person's own
   settings must be measured as they are.
3. **Nothing of ours inside the DAW.** A tool that can crash a session is disqualified (ten of ten
   hosted effects crashed Live).
4. **More than the DAW already shows.** REAPER's Performance Meter gives exact CPU per plug-in
   instance; other DAWs give at least per-track numbers. A weaker meter has no reason to exist.

## Evidence: every approach, against the four

| Approach | 1 No DAW dependence | 2 No settings moved | 3 Nothing inside | 4 More than the DAW | Record |
| --- | --- | --- | --- | --- | --- |
| Sensor on the master + lateness proxy | ✓ | ✓ | ✗ | ✗ the proxy does not follow load | `research/S2-lateness.md` |
| REAPER extension (real-time CPU) | ✗ REAPER only | ✓ | ✗ | ✗ REAPER shows it | `research/D-timing.md` |
| The Probe (wrapper plug-in) | ✗ crashed Live, per-host quirks | ✗ | ✗ | ✓ per instance | `research/Live-first-look.md` |
| Offline bench + project readers | ✗ one reader per DAW | ✓ | ✓ | ✓ predictive, what-if, per buffer size | `research/rpp-state.md`, `als-state.md` |
| Offline bench + our own plug-in rack | ✓ | ✗ rebuild chains by hand | ✓ | ✓ | (discussed, not built) |
| Outside sampler of the DAW process | ✓ | ✓ | ✓ | ✗ per plug-in file only, weaker than REAPER's meter | (discussed, not built) |
| A timing hook inside the DAW | ✓ | ✓ | ✗ | ✓ | (discussed, not built) |

The underlying fact: **which instance of a plug-in is running is known only inside the DAW
process.** Per-instance numbers in a running session therefore need either the DAW's cooperation
(its meter: requirement 4 fails) or code inside the DAW (requirement 3 fails). Measuring outside
the session needs the person's settings, which live only in per-DAW project files (requirement 1)
or must be re-entered (requirement 2). No engineering removes this; one requirement must give,
and the person judged that a product without all four is not worth building.

Also on the record: the offline benchmark technique on its own already exists as free software
(PlugPerf, `research/offline-analyzer-scouting.md`), so the bench alone is not a product either.

## Alternatives considered on the last day

- **Give up requirement 1:** keep the REAPER and Live readers as the product's input (proven:
  13,455 of 13,455 parameters arrive exactly, in both DAWs). Rejected: it is the support list again.
- **Give up requirement 3:** a stopwatch hook around each plug-in's audio call, inside any DAW.
  Rejected: our code in the DAW again, with an untested risk that copy-protected plug-ins treat
  the hook as tampering.
- **Give up requirement 4:** the outside sampler. Rejected: less than REAPER already shows.
- **Give up requirement 2:** SessionScope's own rack. Rejected: the Probe's dealbreaker again.

## Decision

SessionScope stops here as a product. The repository stays as it is, with its history, tests
and records, so the work can be reused or the question reopened.

## Consequences

- **No further product work.** Calibration, more project readers, CLAP or VST2 hosting, the
  sampler spike and the HUD re-targeting are all cancelled.
- **What can be reused**, each built, tested and documented:
  - `native/bench/` + `engine/src/bench_runner.*`: hosting any VST3 plug-in safely out of process
    (job object, watchdog, crash and hang reporting), timing it, the engagement check (does the
    plug-in really process?), factory programs, loading a saved state, finding a plug-in by id.
  - `engine/src/rpp_reader.*`, `als_reader.*`, `inflate.*`: every VST3 plug-in's saved state out
    of a REAPER project or an Ableton Live set (formats in `research/rpp-state.md` and `als-state.md`).
  - `engine/hud/`: a Direct3D 11 + DirectComposition strip of modules, MiniMeters-smooth.
  - The sensors (VST3, CLAP, AU), the REAPER extension, the validators and test harnesses.
- **What was learned** is in `docs/what-failed.md`, including the last day's reasoning.

## Review when

- A DAW vendor opens a per-plug-in performance API that third parties can read (requirement 4
  becomes reachable without code inside the DAW), or
- the person decides one of the four requirements can give after all, or
- the reusable parts are wanted for a different audio tool.
